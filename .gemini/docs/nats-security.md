# NATS JetStream ရဲ့ လုံခြုံရေး (Security)

NATS ရဲ့ လုံခြုံရေးစနစ်ကို အဓိက အပိုင်း (၄) ပိုင်းနဲ့ ဖွဲ့စည်းထားပါတယ်။

## ၁။ စစ်ဆေးအတည်ပြုခြင်း (Authentication - Who are you?)
Client တစ်ခုက NATS server ဆီ ချိတ်ဆက်တဲ့အခါ သူဘယ်သူလဲဆိုတာကို အောက်ပါနည်းလမ်းတွေနဲ့ သက်သေပြနိုင်ပါတယ်။
- **Username & Password:** အခြေခံအကျဆုံး နည်းလမ်းဖြစ်ပါတယ်။
- **Token-based:** ရိုးရှင်းတဲ့ token တစ်ခုတည်းကို သုံးပြီး ချိတ်ဆက်တာပါ။
- **NKEYs:** ဒါကတော့ Public-Private Key စနစ် (Ed25519) ကို သုံးတာဖြစ်ပြီး password ပေးပို့စရာမလိုဘဲ ပိုမိုလုံခြုံပါတယ်။
- **Decentralized JWT:** အကောင့်တွေ၊ user တွေနဲ့ သူတို့ရဲ့ လုပ်ပိုင်ခွင့်တွေကို JWT (JSON Web Token) ထဲမှာ ထည့်သွင်းပြီး စစ်ဆေးတဲ့ အဆင့်မြင့်စနစ် ဖြစ်ပါတယ်။

## ၂။ လုပ်ပိုင်ခွင့် သတ်မှတ်ခြင်း (Authorization - What can you do?)
ချိတ်ဆက်ပြီးသွားတဲ့အခါ အဲဒီ user က ဘာတွေလုပ်ခွင့်ရှိသလဲဆိုတာကို ကန့်သတ်နိုင်ပါတယ်။
- **Subject Permissions:** User တစ်ယောက်ချင်းစီကို ဘယ် Subject ပေါ်မှာ message ပို့ခွင့် (Publish) ရှိတယ်၊ ဘယ် Subject ကို ဖတ်ခွင့် (Subscribe) ရှိတယ်ဆိုတာ အသေးစိတ် သတ်မှတ်နိုင်ပါတယ်။ ဥပမာ - `whatsapp.commands.company_A.>` ကိုပဲ ဖတ်ခွင့်ပေးပြီး အခြား ကုမ္ပဏီ data တွေကို ဖတ်ခွင့်မပေးတာမျိုးပါ။
- **Connection Limits:** User တစ်ယောက်က connection ဘယ်နှစ်ခုပဲ ယူနိုင်တယ်၊ message ဘယ်လောက်ပဲ ပို့နိုင်တယ်ဆိုတာကိုပါ ကန့်သတ်ထားနိုင်ပါတယ်။

## ၃။ အကောင့်များဖြင့် ခွဲခြားခြင်း (Multi-tenancy with Accounts)
ဒါက NATS ရဲ့ အကောင်းဆုံး လုံခြုံရေး လုပ်ဆောင်ချက်တစ်ခုပါ။
- **Isolation:** `Account` တစ်ခုနဲ့တစ်ခုကြားမှာ data တွေဟာ လုံးဝ သီးခြားစီ ဖြစ်နေပါတယ်။ Account A ထဲက message တွေကို Account B က ဘယ်လိုမှ လှမ်းဖတ်လို့ မရပါဘူး (Cloud ပေါ်မှာ tenant တွေ ခွဲထားသလိုမျိုးပါ)။
- **Service Sharing:** လိုအပ်ရင်တော့ Account တစ်ခုကနေ အခြားတစ်ခုဆီကို data အချို့ကို စနစ်တကျနဲ့ `Export/Import` လုပ်ပြီး မျှဝေနိုင်ပါတယ်။

## ၄။ ဒေတာဝှက်ခြင်း (Encryption)
- **TLS/SSL (In-transit):** Client နဲ့ Server ကြားမှာ သွားလာနေတဲ့ data အားလုံးကို TLS သုံးပြီး ဝှက်ထားနိုင်တဲ့အတွက် ကြားဖြတ်ခိုးယူလို့ မရပါဘူး။
- **At-Rest Encryption:** JetStream က disk ပေါ်မှာ message တွေ သိမ်းတဲ့အခါမှာလည်း data တွေကို ဝှက်ပြီး သိမ်းထားနိုင်ပါတယ်။

## ၅။ အကောင်းဆုံး လိုက်နာရမည့် အချက်များ (Best Practices)
- **No Cleartext:** Password သို့မဟုတ် Token တွေကို configuration ဖိုင်တွေထဲမှာ cleartext အနေနဲ့ မထားပါနဲ့။ Environment variables တွေကို သုံးပါ။
- **Least Privilege:** User တစ်ယောက်ကို လိုအပ်တဲ့ Subject တစ်ခုတည်းမှာပဲ ခွင့်ပြုချက်ပေးပါ။ `>` (wildcard) တွေကို အလွန်အကျွံ မသုံးပါနဲ့။
- **Rotate Keys:** NKEYs သို့မဟုတ် JWT တွေကို ပုံမှန် အသစ်လဲလှယ်ပေးပါ။

## အနှစ်ချုပ်
NATS ဟာ ရိုးရှင်းပေမယ့် လုံခြုံရေးပိုင်းမှာ Enterprise-grade ရှိပါတယ်။ ဒီ project မှာ အသုံးပြုသူတွေရဲ့ WhatsApp data တွေ လုံခြုံဖို့အတွက် **NATS Accounts** နဲ့ **Subject Permissions** တွေကို စနစ်တကျ အသုံးချနိုင်ပါတယ်။
