# NATS JetStream ရဲ့ ချဲ့ထွင်နိုင်စွမ်း (Scalability)

NATS JetStream ဟာ အလွန်သေးငယ်တဲ့ အသုံးချမှုတွေကနေ အလွန်ကြီးမားတဲ့ Enterprise စနစ်တွေအထိ ချဲ့ထွင်အသုံးပြုနိုင်အောင် (Scalable ဖြစ်အောင်) တည်ဆောက်ထားတာ ဖြစ်ပါတယ်။ ၎င်းရဲ့Scalability ကို အောက်ပါ အချက်တွေနဲ့ တိုင်းတာနိုင်ပါတယ်။

## ၁။ Clustering နှင့် High Availability (အစုအဖွဲ့လိုက် အလုပ်လုပ်ခြင်း)
NATS ဟာ Cluster အနေနဲ့ အလုပ်လုပ်နိုင်ပါတယ်။ Server အများအပြားကို တစ်ခုတည်းသော စနစ်အနေနဲ့ ချိတ်ဆက်ထားနိုင်ပါတယ်။
- **Raft Consensus:** JetStream ဟာ Raft algorithm ကို သုံးပြီး cluster ထဲက server တွေကြားမှာ message တွေကို ထပ်တူကျအောင် (replication) လုပ်ဆောင်ပါတယ်။
- **Fault Tolerance:** Server တစ်ခု ပျက်သွားရင်တောင် အခြား server တွေက အလိုအလျောက် ဆက်လက် တာဝန်ယူပေးတဲ့အတွက် စနစ်ကြီးတစ်ခုလုံး ရပ်တန့်မသွားစေပါဘူး။

## ၂။ Horizontal Scaling (အလျားလိုက် ချဲ့ထွင်ခြင်း)
User တွေ ပိုများလာပြီး message တွေ ပိုများလာတဲ့အခါ server အသစ်တွေကို Cluster ထဲ ထပ်ထည့်ရုံနဲ့ စနစ်ရဲ့ လုပ်ဆောင်နိုင်စွမ်းကို မြှင့်တင်နိုင်ပါတယ်။
- **Subject Partitioning:** Message တွေကို Subject တွေအလိုက် ခွဲခြားပြီး မတူညီတဲ့ server တွေဆီကို ဖြန့်ဝေပေးပို့နိုင်တဲ့အတွက် workload ကို မျှဝေခံနိုင်ရည် ရှိပါတယ်။

## ၃။ အလွန်မြင့်မားသော စွမ်းဆောင်ရည် (High Throughput)
NATS ဟာ အခြား messaging systems တွေ (ဥပမာ - Kafka သို့မဟုတ် RabbitMQ) နဲ့ ယှဉ်ရင် အလွန်ပေါ့ပါးပါတယ်။
- **Millions of messages:** စက္ကန့်ပိုင်းအတွင်း message သန်းပေါင်းများစွာကို သယ်ဆောင်ပေးနိုင်တဲ့ စွမ်းရည်ရှိပါတယ်။
- **Low Latency:** Message တစ်ခု ပို့လိုက်တာနဲ့ ရောက်ရှိသွားတဲ့ကြားက ကြာချိန် (Latency) အလွန်နည်းပါတယ်။

## ၄။ Leaf Nodes (ဖြန့်ကြက်ခြင်း)
အဝေးမှာရှိတဲ့ ရုံးခွဲတွေ ဒါမှမဟုတ် မတူညီတဲ့ Cloud Region တွေမှာရှိတဲ့ server တွေကို Main Cluster နဲ့ ချိတ်ဆက်ဖို့ **Leaf Nodes** စနစ်ကို သုံးနိုင်ပါတယ်။ ဒါက data တွေကို ဗဟိုမှာပဲ စုမနေစေဘဲ လိုအပ်တဲ့နေရာတွေမှာ ဖြန့်ကြက်ထားနိုင်စေပါတယ်။

## ၅။ Resource Management (အရင်းအမြစ် ထိန်းချုပ်မှု)
JetStream မှာ Stream တစ်ခုချင်းစီအလိုက် CPU၊ Memory နဲ့ Disk အသုံးပြုမှုကို ကန့်သတ်ထားနိုင်ပါတယ်။ ဒါကြောင့် စနစ်တစ်ခုက message တွေ အလွန်အမင်း များလာရင်တောင် အခြားစနစ်တွေကို ထိခိုက်မှု မရှိအောင် ကာကွယ်ပေးထားနိုင်ပါတယ်။

## အချုပ်
ဒီ Project မှာ NATS ကို သုံးထားခြင်းအားဖြင့် နောင်တစ်ချိန်မှာ WhatsApp Connection တွေ သောင်းနဲ့ချီပြီး များလာရင်တောင် Server အင်အား ထပ်ဖြည့်ရုံနဲ့ စနစ်တစ်ခုလုံးကို အလွယ်တကူ ချဲ့ထွင်သွားနိုင်မှာ ဖြစ်ပါတယ်။
