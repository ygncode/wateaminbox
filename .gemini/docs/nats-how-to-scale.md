# NATS JetStream ကို ဘယ်လို ချဲ့ထွင်မလဲ (How to Scale)

NATS ကို လက်တွေ့ ချဲ့ထွင်ဖို့အတွက် အောက်ပါ နည်းလမ်း (၄) ခုကို အဓိက အသုံးပြုနိုင်ပါတယ်။

## ၁။ Cluster တည်ဆောက်ခြင်း (Horizontal Scaling)
Server တစ်လုံးတည်း သုံးမယ့်အစား Server ၃ လုံး သို့မဟုတ် ၅ လုံးကို စုပေါင်းပြီး Cluster တည်ဆောက်ရပါမယ်။ 
- **Replication:** Stream တစ်ခုကို တည်ဆောက်တဲ့အခါ `Replicas: 3` လို့ သတ်မှတ်လိုက်ရင် အဲဒီ data တွေကို server ၃ လုံးမှာ ပွားပြီး သိမ်းထားပေးမှာ ဖြစ်ပါတယ်။
- **High Availability:** Server တစ်လုံး ပျက်သွားရင်တောင် ကျန်တဲ့ ၂ လုံးက အလုပ်ကို ဆက်လုပ်နေမှာ ဖြစ်ပါတယ်။

## ၂။ Queue Groups အသုံးပြုခြင်း (Consumer Scaling)
Message တွေ အလွန်အမင်း များလာတဲ့အခါ message ဖတ်တဲ့ worker တွေ (ဥပမာ - Go services) ကို အရေအတွက် တိုးချဲ့နိုင်ပါတယ်။
- **Load Balancing:** Worker တွေ အားလုံးကို `Queue Group` တစ်ခုတည်းအောက်မှာ ထားလိုက်ရင် NATS က message တွေကို worker တွေကြားထဲမှာ အညီအမျှ ခွဲဝေပေးပို့မှာ ဖြစ်ပါတယ်။
- ဒါကြောင့် worker တစ်ခုတည်းမှာ load အများကြီး မကျတော့ဘဲ လုပ်ဆောင်ချက်တွေ ပိုမြန်လာမှာ ဖြစ်ပါတယ်။

## ၃။ အရင်းအမြစ်များကို ခွဲဝေခြင်း (Multi-tenancy)
Project ထဲမှာ ကုမ္ပဏီတွေ အများကြီး ရှိလာတဲ့အခါ (Multi-tenant) တစ်ခုနဲ့တစ်ခု load မပိအောင် ခွဲခြားနိုင်ပါတယ်။
- **Accounts:** NATS ရဲ့ `Accounts` စနစ်ကို သုံးပြီး ကုမ္ပဏီတစ်ခုချင်းစီအတွက် သီးသန့် အခန်းကဏ္ဍတွေ ခွဲခြားထားနိုင်ပါတယ်။ ဒါက Security အတွက်ရော Performance အတွက်ပါ ကောင်းမွန်ပါတယ်။

## ၄။ Leaf Nodes များဖြင့် နယ်မြေဖြန့်ကြက်ခြင်း (Geo-distribution)
အကယ်၍ သင့်ရဲ့ စနစ်က နိုင်ငံအနှံ့ သို့မဟုတ် ကမ္ဘာအနှံ့မှာ ရှိနေမယ်ဆိုရင်-
- **Local Processing:** User နဲ့ နီးစပ်ရာ နေရာမှာ Leaf Node တစ်ခု ထားရှိပြီး data တွေကို အဲဒီမှာတင် အရင် process လုပ်စေနိုင်ပါတယ်။
- **Syncing:** အဲဒီ Leaf Node ကမှတစ်ဆင့် Main Cluster ဆီကို လိုအပ်တဲ့ data တွေကိုပဲ ပြန်ပို့စေခြင်းဖြင့် bandwidth ကို ချွေတာနိုင်ပါတယ်။

## နည်းပညာဆိုင်ရာ သတ်မှတ်ချက်များ
- **Memory vs Disk:** ခေတ္တခဏပဲ သိမ်းဖို့လိုတဲ့ message တွေကို `Memory Storage` သုံးပြီး၊ ရေရှည်သိမ်းရမယ့် data တွေကို `File Storage` (Disk) သုံးဖို့ ရွေးချယ်နိုင်ပါတယ်။
- **Limits:** Stream တစ်ခုချင်းစီမှာ `MaxMsgs`, `MaxBytes` သတ်မှတ်ပြီး server ရဲ့ memory ပြည့်မသွားအောင် ထိန်းချုပ်ထားရပါမယ်။

## အနှစ်ချုပ်
ချဲ့ထွင်ဖို့အတွက် ပထမဆုံး server ၃ လုံးနဲ့ Cluster စတင်ပါ။ ပြီးရင် message ဖတ်တဲ့ worker တွေကို `Queue Group` နဲ့ ပွားပြီး အသုံးပြုပါ။ ဒါဆိုရင် သင့်ရဲ့စနစ်ဟာ အသုံးပြုသူ သန်းချီတဲ့အထိ ခံနိုင်ရည် ရှိသွားမှာ ဖြစ်ပါတယ်။
